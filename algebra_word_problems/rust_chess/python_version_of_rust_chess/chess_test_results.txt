7. WHAT I LEARNED (PYTHON VS RUST, AND THE ALGEBRA TRANSFER)
====================================================================================================

7.1 Python port fidelity
  - board / strategies / exchange / evaluate / history / normalize / index / lists34 / archive / drill / main
    are a line-faithful port of the Rust modules. No third-party chess library.
  - On seed-1 / 100 drill games the entire position index matched Rust byte-for-key and status-for-status.
  - verify_kpk retrograde truth matches Rust exactly (111282 / 54394).
  - Move field `from` is `from_` in Python (keyword). Index file format remains FORMING-CHESS-INDEX 2.

7.2 Speed
  - Rust release drill: about 8 minutes for 1.4M games on this machine (~0.3 ms/game).
  - Python after optimisations (early-out attacked_by, occupied-square move gen, skip castling fixups when
    castling==0, cached KPK start list): about 18 ms/game on this machine.
  - So a full 1.4M solve in Python is hours, not minutes. That is language/runtime cost, not a wrong proof.

7.3 Algebra transfer (same proposal as the Rust report, part 7)
  - Keep the four-list / archive / proof-by-substitution design; implement the algebra operator in Python inside
    the calculator. Do not reuse the chess board code as a library for word problems.
  - Exact-wording archive hits are strong; new wordings need better cues than plain TF-IDF alone.
